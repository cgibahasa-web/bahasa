# 2027 CGI BAHASA Conference 웹사이트 제작 실행계획

작성일: 2026-09-18
문서 성격: 폴더 자료 검토에 따른 제안. 기존 기획안의 정책을 새롭게 승인하거나 실제 사이트를 개설한 문서가 아니다.

사용자 지정 개발 환경: VS Code에서 GPT 및 Claude를 활용하는 직접 개발 방식. 기존 자료의 아임웹 도입안은 이번 실행계획에 적용하지 않는다.

## 1. 추진 방향

인도네시아어권 참가자가 행사 취지와 일정을 이해하고, 자신의 거주지와 개인·단체 구분에 맞게 신청한 뒤 참가 준비까지 할 수 있는 모바일 중심 사이트를 만든다.

- 1차 공개: 대회 소개, 예정 일정, 장소, 참가 안내, 공식 문의처를 담은 안내 사이트.
- 2차 공개: 정책과 결제 검증을 마친 뒤 개인·단체 등록, 결제, 등록 확인, 초청장 신청을 추가.
- 권장 언어: 인도네시아어 기본, 영어 전환. 운영진 관리 화면은 한국어를 선호하되 플랫폼 검증 시 확인.
- 시각 방향: 기존 시안의 네이비·골드·아이보리 색상과 아치 모티프를 활용. 모바일 본문은 읽기 편한 밝은 배경, 실제 기도원 사진, 짧은 문단으로 구성.
- 사이트 명칭은 ‘2027 CGI BAHASA Conference’를 제안하며 공식 영문 표기는 주최 측 확인 후 통일.

## 5. VS Code + GPT + Claude 개발 방식

작업 환경은 VS Code로 통일하고 소스는 Git으로 관리한다. 화면, 서버 처리, 데이터 저장소, 관리자 화면, 결제·이메일 연동을 분리해 설계한다. 구체적인 프레임워크·호스팅·데이터베이스 제품은 개발자의 익숙함, 운영 비용, 결제 연동 조건을 검토한 뒤 선정한다. 이 기획 단계에서는 제품 계약이나 설치를 진행하지 않는다.

### 개발 순서

1. 프로젝트에 요구사항, 확정 정보, 미확정 정책, 화면 목록을 문서로 저장한다.
2. 개발 실행 방법, 폴더 구조, 환경설정 예시, Git 저장소를 준비한다.
3. 공통 색상·글꼴·버튼·메뉴와 모바일 기본 화면을 만든다.
4. 임시 데이터로 홈, 소개, 일정, 참가 안내, 문의 화면을 완성한다.
5. 인도네시아어·영어 문구를 분리하고 주소·언어 전환·오류 안내를 연결한다.
6. 신청서와 데이터 저장을 연결하고 개인·단체 참가자 구조를 구현한다.
7. 관리자 로그인·권한, 명단 조회·수정·내려받기, 정원 관리를 구현한다.
8. 결제 시험 환경에서 결제·실패·취소·환불과 결제사 통지를 연결한다.
9. 신청 확인 이메일과 안전한 등록 조회, 초청장 신청 처리를 연결한다.
10. 시험용 배포 주소에서 이용자 흐름을 검증한 후 운영 환경과 도메인으로 공개한다.

결제 화면에서 돌아온 결과만으로 결제 완료로 처리하지 않는다. 서버에서 결제사 기록을 확인하고 같은 통지가 반복되어도 중복 등록·정산되지 않게 설계한다. 공개 안내 사이트는 신청·결제 기능 완성 전에 별도로 공개할 수 있다.

### GPT·Claude 협업 규칙 제안

- 두 도구가 같은 요구사항·정책 문서를 읽도록 한다. 대화에만 남은 결정은 문서에 반영한다.
- 한 기능은 한 도구가 구현하고 다른 도구가 변경사항과 실패 사례를 검토하는 식으로 번갈아 활용한다. 고정된 모델 우열을 전제로 역할을 나누지 않는다.
- 같은 파일을 두 도구가 동시에 고치지 않는다. 작업 범위·완료 조건·수정 파일을 명시하고 작은 단위로 저장한다.
- 실제 참가자·여권 자료 대신 가상 데이터로 개발·검토한다. 비밀번호와 결제 비밀키는 코드 및 저장소 밖에서 관리한다.
- AI가 완료했다고 보고해도 실제 브라우저에서 신청·조회·취소를 실행해 확인한다.

### 첫 공개 범위와 후속 범위

첫 공개는 행사 안내·프로그램·장소·참가 조건·문의·언어 전환으로 제한한다. 다음 단계에서 등록·결제·관리자·초청장 신청을 추가한다. 라이브 방송 영역, 사진 갤러리, 현장 QR 체크인 등은 실제 운영 필요를 확인한 뒤 별도 범위로 결정한다.

비용은 개발·디자인·번역, 도메인·호스팅·데이터 저장, 이메일 발송, 결제 수수료, 운영 유지보수로 구분한다. 기존안의 PayPal과 국내 결제는 후보 요구사항으로 유지하되, 주최 측 계약 가능 여부와 실제 해외 결제·환불 시험을 통과한 뒤 확정한다.

## 6. 등록·운영 흐름

개인: 언어 선택 → 참가 조건 확인 → 신청 정보 입력 → 선택 프로그램 → 금액 확인·동의 → 결제 → 확인번호·안내 → 등록 조회.

단체: 대표자 정보 → 인원·금액 확인 → 명단 등록 → 일괄 결제 → 대표자 안내 → 명단 변경·취소 처리. 최소 인원, 미완성 명단 허용 여부, 명단 제출 기한을 먼저 결정한다.

신청 상태는 접수·결제 대기·결제 완료·취소·환불로 관리하고, 결제 완료 화면만으로 명단을 확정하지 않도록 결제 기록과 대조한다. 단체 부분 취소, 중복 결제, 결제 실패 후 재시도, 마감 직전 결제의 처리 기준도 마련한다.

기본 등록은 이름, 거주 국가, 연락처, 소속, 참가 유형 등 필요한 항목 중심으로 설계한다. 여권번호·사본은 일반 등록의 공통 필수항목으로 넣지 않고 초청장 업무상 필요 여부를 검토한 뒤 별도 제한된 절차로 취급하도록 제안한다. 수집 항목·접근 담당·보관 기간·삭제 방법과 관련 문구는 실제 운영에 맞게 확정한다.

초청장: 신청 → 담당자 확인 → 보완 요청 → 발급 → 전달 기록. 실제 비자 안내 원고는 공개 시점의 공식 안내 확인 후 작성하며, 이 문서에서 비자 종류나 발급 요건을 확정하지 않는다.

운영 역할 제안: 한국 담당은 기도원·현장 정보 취합, 현지 담당은 인도네시아어 감수·현지 참가자 안내, 재정 담당은 정산·환불, 등록 담당은 명단·초청장 접수, 제작자는 사이트 유지보수. 한사무엘1 목사·한사무엘2 간사의 실제 역할은 별도 지정이 필요하다.
